# NJS Home v4.1 — Korean visual/copy benchmark

Status: INTERNAL UX BENCHMARK
Date: 2026-09-27
Applies to: D-048 / SD-005 / P30 Home v4.1

## 1. Why this pass exists

The previous v4 prototype verified rough information architecture, but still looked like a sequence of generic sections and cards. That is not enough for user review. Home v4.1 must combine information architecture, copy context, visual rhythm, images, and mobile behavior.

The goal is not to copy one Korean service. Each benchmark is used for a different job.

## 2. Benchmark roles

### Toss — narrative continuity across many services
Official 2026 homepage renewal principle: stop explaining many services as separate items and connect them into one story; let product screens and visuals explain the service while scrolling.

Adopt for NJS:
- Home should feel like one argument, not a service catalog.
- Each section should answer the question raised by the previous section.
- Use actual service/product screens and real imagery instead of repeated generic cards.
- Allow strong changes in scale, background, and layout to signal a new chapter.

Do not copy:
- large-enterprise motion density
- super-app breadth

Sources:
- https://toss.im/newsroom/toss-new-homepage
- https://toss.im/

### LongBlack — Korean narrative copy + editorial rhythm
Current About flow: problem context → desired user identity/change → actual content examples → user proof/metrics → features → plan/FAQ.

Adopt for NJS:
- short sentences still need cause-and-effect continuity.
- copy should create the need for the next section.
- show actual content titles early, not only describe “Knowledge”.
- use user identity/change carefully: the goal is not more information, but better judgment and stronger business/brand decisions.
- mix text with real content imagery/screens instead of grids of explanatory cards.

Do not copy:
- poetic/literary tone
- artificial urgency such as expiring content unless product logic requires it

Sources:
- https://longblack.co/about
- https://longblack.co/note/1906

### Publy — start from the user’s current problem
Current home surfaces “오늘의 고민 해결 인기 콘텐츠” and asks users to set career context for recommendations.

Adopt for NJS:
- early Home entry should be problem-led, not taxonomy-led.
- “브랜드가 선택받지 못한다 / 플랫폼 의존을 줄이고 싶다 / 마케팅을 다시 구조화하고 싶다” is more useful than introducing internal modules first.
- Knowledge should feel immediately usable.

Do not copy:
- career-membership framing
- content-feed density

Source:
- https://publy.co/

### Trevari — explain experience through actual verbs
Trevari explains its value through the sequence “읽고, 쓰고, 대화하고, 친해져요” and supports it with concrete member behavior.

Adopt for NJS:
- Program/Community should be explained as behavior, not abstract “성장/교류”.
- Prefer concrete sequences such as “읽고 → 적용하고 → 기록하고 → 피드백 받고 → 다른 경험과 연결”.
- explain why people are together before showing community UI.

Do not copy:
- offline club identity
- social relationship as the primary site promise

Sources:
- https://trevari.co.kr/hello
- https://m.trevari.co.kr/

### 29CM — editorial image/copy integration
29CM Showcase uses strong photography/video, short contextual copy, and embeds products inside an editorial story instead of separating “story” and “commerce” completely.

Adopt for NJS:
- images must prove or deepen meaning: book, lecture, author/work, actual service UI.
- avoid decorative stock photography.
- products/courses can appear inside the story at the moment they become relevant.
- vary image scale: one large visual can be stronger than several equal cards.

Do not copy:
- fashion-magazine tone
- image-first treatment where clarity of a knowledge service is lost

Sources:
- https://www.29cm.co.kr/
- https://www.29cm.co.kr/content/29-showcaseplus/2026/06/summerlook

### CLASS101 — make learning value and scope explicit
CLASS101 clearly states the learning promise, product breadth, proof and conversion.

Adopt for NJS:
- Course area must make “what changes after learning” concrete.
- learning product UI and resume/progress should be visible where relevant.
- conversion can be explicit after enough context exists.

Do not copy:
- discount-led Home
- large catalog density

Sources:
- https://class101.net/ko/pages/hub-page
- https://class101.net/ko

### MKYU — personal brand ecosystem reference, but not a visual model
MKYU is useful because one public figure connects learning, community, event, store and personal brand.

Adopt for NJS:
- personal authority can support a broader learning/community ecosystem.
- explain how a newcomer can use the service.

Do not copy:
- traditional education-portal menu density
- generic “성장” language

Source:
- https://www.mkyu.co.kr/main/page.jsp?code=greeting

## 3. Visual rules for NJS v4.1

1. Do not use identical cards for every module.
2. One section = one primary message and one visual reason to exist.
3. Real assets before decoration: author/work photo, book cover, lecture image, actual Knowledge/Course/Program UI.
4. Alternate rhythm intentionally: text-led → content-led → dark POV chapter → image/proof → learning/product → application/relationship.
5. Use large images sparingly. One strong image can carry an entire section.
6. Keep Home editorial, not dashboard-like. My Space is the dashboard.
7. On mobile, reduce simultaneous options rather than merely stacking desktop blocks.
8. Community is not an empty feed preview. Show its purpose and examples.
9. Products are contextual: book/course/program appear only when the narrative reaches deeper learning/application.
10. Store is not a top-level Home chapter.

## 4. Copy rules for NJS v4.1

1. Short does not mean context-free.
2. The next sentence should normally answer or deepen the previous sentence.
3. Avoid category dumping such as “브랜딩·마케팅·소비자심리·사업운영...” unless the sentence explains why those areas belong together.
4. Use one concrete problem before one abstract principle.
5. Avoid “성장, 인사이트, 혁신, 본질” unless followed by a concrete meaning.
6. Never fabricate a Max quote. Distinguish authored copy from verified source language.
7. Commerce experience is evidence, not the top-level identity.
8. Do not overcorrect into design-branding. Keep customer, market, distribution, business operation and measurable behavior in frame.
9. Text around images must explain why that image matters.
10. Korean naturalness takes priority over translated global SaaS phrasing.

## 5. Proposed Home v4.1 narrative

### Chapter A — orientation
Headline direction: “팔기 전에, 선택받을 이유부터.”
Context: platforms and tactics change; a business needs something that remains — reasons to choose, customer relationship, judgment.
Primary action: find a useful article/question now.

### Chapter B — start from the current problem
Three problem-led entrances, not four equal product cards.
- 브랜드가 선택받지 못한다
- 플랫폼 밖에서 고객을 만나고 싶다
- 마케팅을 다시 구조화하고 싶다

### Chapter C — immediate proof of value
Show one large Knowledge feature + two secondary questions. This is not “Knowledge 소개”; it is actual thinking the visitor can sample.

### Chapter D — point of view + proof
Explain why Max looks at problems this way, using actual career/business/writing/lecture evidence. Avoid credential wall immediately below Hero.

### Chapter E — deeper learning
Book and Course appear as two different ways to go deeper. Use actual book cover and a course UI mock/real screen.

### Chapter F — application and relationship
Explain Program and Community through behavior: read → apply → record → feedback → compare experiences.

### Chapter G — professional/B2B
Speaking, corporate education, collaboration. Keep it explicit but late.

### Chapter H — recovery/footer
Support, orders, cancellation/refund, policies and low-frequency links.

## 6. Mobile-specific v4.1 rules

- First viewport: identity/value + one action. No menu wall.
- Second/third viewport: immediate useful content, not credentials.
- Keep one primary CTA per chapter.
- Featured Knowledge: 1 main item + “더 보기”, not 3 equal cards.
- Proof becomes a short story with one image, not a timeline grid.
- Book/Course should be swipe/stack only if hierarchy remains obvious.
- Program/Community are shown after the visitor has seen free value.
- Mobile community entry may be more visible for returning members, but public first-visit Home should not assume community intent without data.
- Browser back and in-page state must work naturally.

## 7. Review contract

User review should not ask for professional design judgment. Review mode should ask only:
- 5초 안에 무엇을 다루는 서비스인지 이해되는가?
- 다음 내용을 더 보고 싶은가?
- 앞 문장과 뒤 문장이 자연스럽게 이어지는가?
- 이미지가 왜 이 위치에 있는지 이해되는가?
- 다음 행동이 하나로 보이는가?

Expert review remains responsible for grid, spacing, hierarchy, copy density, accessibility, mobile targets, state/recovery, and cross-domain continuity.
